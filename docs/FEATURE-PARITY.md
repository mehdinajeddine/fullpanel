# Feature parity ledger

Baseline: Easypanel image **2.38.0**, digest recorded in [reference analysis](REFERENCE-ANALYSIS.md), and official docs read on **2026-11-08**. FullPanel is an original implementation. This ledger tracks outcomes, not visual duplication or API compatibility.

## Status and evidence rules

Updated against the implementation and the verification runs below on **2026-11-08**. Status applies to the stated scope, not the whole reference product. `partial` means a stated subset works. `implemented` means the acceptance criterion works in the intended runtime. `verified` additionally has a named passing test or recorded manual result. An API-only implementation does not satisfy an end-user workflow criterion. The main browser suite uses the explicit demo adapter; the dedicated restoration browser fixture and separate Docker checks exercise the real adapter. No completion percentage should collapse these distinctions.

Priority: **P0** usable secure foundation; **P1** core operational parity; **P2** advanced parity. Evidence labels: **D** official documentation; **S** installer/image static inspection; **I** FullPanel product requirement inferred from the task. Links in the feature column identify the primary reference. Static evidence is described in `REFERENCE-ANALYSIS.md`.

## Current boundaries

FullPanel currently operates Docker standalone containers and a restricted inline Compose subset, not a Swarm cluster. Container replacement can interrupt traffic and does not establish application readiness. No zero-downtime or complete failure-rollback guarantee is made.

Still pending are archive uploads, GitHub App/OAuth connection, automatic builders, database/Compose rollback, real Docker terminal verification and named scripts, the remaining public-network/IPv6/offline/diagnostic work for automatic test domains, further proxy middleware, MCP, remote backup providers, managed WordPress/Box, clustered workers and host-upgrade operations. Verified source authentication covers HTTPS Git-token scope, a real private SSH-server fixture and pulled images. Private hosted HTTPS/live hosted-provider SSH accounts, private build bases and private Compose images remain unverified or unsupported as stated above. Migration adapters are a subsequent planned milestone. Some configuration fields are present before the full reference workflow exists; their ledger rows remain partial or pending.

E2 uses native tools directly; E9 exercises the product restoration driver. Database restoration adopts the backup credentials, retains old volumes and requires fresh verified metadata. Remaining engine and browser/process-crash evidence is recorded separately in VERIFICATION.md. The scheduler is tested with a controlled clock; it does not claim a production-duration soak test. HTTP proxy success does not verify certificate issuance. Demo browser success does not by itself verify Docker behavior.
