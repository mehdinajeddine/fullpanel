- The 22 main browser workflows use the demo runtime, with explicit controlled sample fixtures for metrics display. The dedicated restoration and release browser tests, Docker scripts and package test verify real infrastructure operations. The SSH/Inter baseline image passed the package fixture; the subsequent test-URL source increment has its separate evidence above.
- Initial public HTTPS/ACME issuance was exercised for two AWS test hostnames as described above. Renewal, arbitrary DNS-provider configurations and comprehensive certificate-failure diagnostics remain unverified. The bundled resolver reads `ACME_EMAIL` from deployment configuration; the saved `letsEncryptEmail` setting does not currently reconfigure it.
- New applications can receive a saved sslip.io HTTP test route after an administrator configures a public IPv4; a custom `baseDomain` takes priority. This removes per-service DNS editing but still requires a reachable server and proxy. IP discovery, IPv6, a local-offline endpoint and public service/ACME diagnostics remain pending in [R08](specs/14-default-test-domain.md). Provider DNS and local routing proofs above do not establish public application reachability or certificate issuance.
- Native GitHub tests use locally signed fixture deliveries. GitHub App/OAuth installation and delivery from GitHub to an owned public HTTPS domain remain unverified/unsupported. Replay deduplication retains 256 accepted receipts per configured service.
- Application rollback requires local retained images and compatible managed mounts; it preserves current volume data and does not reverse migrations. Database/Compose rollback, automatic release-retention limits and cross-host image recovery remain absent. Interrupted deploys invalidate the active-release claim and block configuration/data changes until redeploy; automatic reconciliation of every deployment phase is not implemented.
- Private hosted HTTPS deployment remains untested; exact-repository askpass behavior and public Git deployment are verified separately. Private SSH deployment is verified against a disposable local OpenSSH server, including generated keys and strict host pins, but not a live private GitHub/GitLab account. Imported SSH keys, agents/certificates/jump hosts, private Dockerfile base images and private Compose images remain unsupported.
- SSH identity staging is removed on normal exit and reaped after the next writer-locked startup following a panel crash; plaintext files can remain until that restart. Git timeout and panel death terminate the supervised SSH child in the tested cases. Killing the auxiliary wrapper itself causes a failed job and key cleanup, but an SSH process can remain orphaned and its termination is not confirmed. The product does not kill arbitrary host PIDs, and no complete process-erasure guarantee is claimed.
- The Docker terminal is an experimental prototype, disabled by default. An administrator must explicitly set `HARBORLIGHT_EXPERIMENTAL_TERMINAL=true` to enable it; this does not establish stable support. Real Docker PTY behavior and durable recovery of sessions after panel failure remain unverified. The default API capability is disabled and a WebSocket upgrade is refused with 409; those gates are tested independently of injected-runtime protocol/lifecycle tests.
- MySQL 8.4.13, MariaDB 11.4.13 and MongoDB 8.3.13 pass local and remote real engine and restoration fixtures. MongoDB requires a compatible host kernel as recorded above. These are small, single-node, same-image tests; they do not establish large-dump, MySQL GTID, replication, sharding or cross-version migration support. Other catalog applications remain unverified.
- Restoration requires recorded local backups with fresh metadata and compatible engines. It does not support uploaded external archives, Compose, cross-version migrations, custom PostgreSQL tablespaces, or tar archives containing links/extended headers. Original volumes are retained and require explicit later cleanup; application archives copy live files without an application-level consistency guarantee.
- Schedules use UTC and a 15-second polling loop. Controlled-clock tests verify scheduling and retention rules; no long-running production soak test has been performed.
- Standalone container replacement can interrupt traffic. Start success is not application readiness, and no zero-downtime guarantee is claimed.
- Project permissions protect the control-plane API. Domain applications share a proxy Docker network and can reach each other directly on that network; operators must be trusted. The panel is not a hostile-tenant isolation boundary.
- Workspace metrics combine Docker CPU statistics with the panel process host's memory/disk measurements, now labelled separately. Service metrics use only verified current service containers. Remote daemons and containerized hosts can have different global measurement scopes; no historical retention is implemented.
- Source and the dated DOCX are published at [mehdinajeddine/fullpanel](https://github.com/mehdinajeddine/fullpanel); no public container image is published. The published SSH/Inter baseline has a fully passing remote CI run, linked above.
